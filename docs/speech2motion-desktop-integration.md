# Speech2Motion in Preacherman

The packaged Windows sidecar connects to the existing installation at
`D:\Codex\speech2motion`. No model or motion database is copied onto C:.

## Use

- Asset → character → Settings → Motion Service shows connection state and reconnects.
- Appearance → Action previews Signature idle, Subtle, Natural or Expressive.
  Hold Apply to save only that character's preference.
- The bottom-right voice conversation uses the selected character's execution and voice.
  Speech motion accompanies the synthesized reply; no transcript is displayed.
- Signature idle disables speech gestures. Other styles affect the next spoken sentence.

## Playback

The current `SpokenConversation` path decodes each synthesized sentence first. Its
actual audio duration is sent through the local binary V3 proxy, with KQ-default
as the source skeleton and python_backend matrices. Motion receives at most
160 ms of initial headroom; it cannot block the audio if unavailable. Frames
follow AudioContext.currentTime, including late arrivals. A cancelled sentence
stops its source immediately and fades its last heard pose over 160 ms; even a
network stream that already delivered all frames remains cancellable. A new
character, sentence or preview cannot reuse an old stream's frames.

The adapter layers speech bones over the authored idle and restores their
base pose before each animation-mixer update. Most characters retain upper-body
bindings; Cortana also drives her pelvis, thighs, knees, ankles and toes as
described below. Authored materials and textures are untouched. Sculpted Nier
print figures use torso motion only. Baseline mappings are generated by
`python tools/speech2motion/build-character-bindings.py`; rerun and review this
when changing a GLB. This validates names, not artistic motion quality on every
frame. English greeting/thanks/affirmation cues map to the installed library's
keywords without translating the spoken reply.

Motion is retrieved/blended from the installed motion library. It is not a new
generative motion model or phoneme-driven facial animation system. Existing
audio-energy lip movement remains in place. Native verification covers Cortana
and the imported DeepSeek rig; other rigs share the verified upper-body mapping
and can be tuned independently through Action.

### Cortana anatomical calibration

Cortana's packaged skin is authored facing +X, whereas the converted KQ source
faces +Z. Her profile applies a +90-degree yaw to the source coordinate frame,
aims arm/forearm/hand reference directions using the existing joint positions,
and maps the lower spine and upper neck to `b_spine0` and `b_neck1`. It does not
change mesh geometry, bind matrices, skin weights, textures, or bone lengths.
The source pelvis rotation is removed from descendant motion, which follows the
target's applied pelvis instead. Source Root turns and world travel are excluded.
Torso, clavicle, neck and wrist rotation limits plus quaternion interpolation
constrain transitions. Other characters
retain their existing bindings; this calibration must not be copied blindly.

Regression tests use the packaged Cortana skeleton and KQ rest pose to check arm
directions, root isolation, wrist limits, interpolation and exact idle restoration.
Three fixed service captures are compared before/after in
`output/cortana-calibration-20261103/`. This corrects retargeting; motion selection,
finger articulation and character-specific acting remain separate work.

### Cortana lower body (2026-11-05)

The Cortana-specific v3 binding adds the pelvis and both complete leg chains.
Thigh, calf and foot reference directions use their anatomical children, retaining
the authored skin and lengths. Pelvis rotation is bounded to 0.3 radians; thighs
to 0.6, knees to 0.95, ankles to 0.55 and toes to 0.35, before the chosen Action
strength. This allows speech-linked weight shifts and leg articulation without
applying large turns or locomotion from the general-purpose motion library.

After the existing entry/release blend, foot and toe support points correct the
pelvis position relative to that frame's authored idle. Soft support weights avoid
abruptly swapping the standing foot. Corrections stay within 0.18 vertical and
0.08 horizontal avatar-root units, are removed before the next mixer update,
and return exactly to idle after interruption. This is bounded in-place support
correction, not walking navigation or a full collision/foot-IK solver.

Regression coverage includes a committed real-service lower-body capture,
source Root isolation, moving knees/ankles, support height, entry/interruption,
position restoration, and unchanged non-Cortana bindings. Native/visual evidence:
`output/cortana-lowerbody-20261105/`.

## Service ownership and lifecycle

| Service | Address | Owner | Stop method |
| --- | --- | --- | --- |
| Preacherman motion proxy | sidecar `/api/motion/speech2motion` | canonical desktop sidecar | close desktop |
| Speech2Motion V3 | `127.0.0.1:18084` | Docker container `speech2motion` | `docker compose -f D:\Codex\speech2motion\compose.yaml stop` |

Startup checks health, reuses a healthy process, and coalesces reconnects. If
needed, the sidecar starts Docker Desktop and runs the fixed compose deployment
without building or pulling images. It never launches the old Python deployment
or replaces another listener. The UI and Home do not wait for Docker. Docker is
shared and is not shut down when Preacherman exits. Temporary CLI children have
bounded timeouts and cancellation. A custom endpoint is health-checked but not
auto-managed.

`GET /api/characters/:id/motion` and `POST` with `{enabled, style}` read/write
the existing character profile store. Credentials, voices and execution choices
are preserved. `GET /api/motion/health` returns readiness and startup status;
`POST /api/motion/connect` initiates a nonblocking reconnect.

Verification artifacts: `output/playwright/speech-motion-20261103/`.
