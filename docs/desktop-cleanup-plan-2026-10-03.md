**S3：把构建来源固定下来。**

**8．R：局部重构的具体范围**

**R1：统一页面映射与命名，保持导航和动效行为。**

当前界面标签与内部身份有历史错位：Task 对应 workspace，Gallery 对应 market，Market 对应 ledger；当前 Task 的组件名称还叫 GallerySurface。

建议整理一份明确的页面注册表，使显示名称、组件、旧路由身份有可检查的对应关系；将明显误导的内部组件名改成当前用途。所有旧 URL、持久化标识和导航行为保留兼容，不用全局字符串替换改掉 market/ledger/workspace。

验收：每个导航目标、前进后退、默认 Home、快速切换、进出动效与当前发布一致。现有设置入口与空预留页也保持原来行为。

**R2：整理旧实现、测试支持与公共样式。**

随 C 的退役清掉仅服务旧页面的导入、局部样式和旧预览入口。将确实只用于测试的模拟器与测试支持归到清晰位置，但先验证调用者，再迁移路径。

共享样式按实际引用处理，不做未经覆盖验证的全局 CSS 清扫；对模型、iframe 内部页面、动态 class 和主题变量尤其保留引用核查。src/settings/settings-v3.css、src/live 契约和当前 runtime patch 工具不会因为主入口没引用就整块删除。

验收：类型检查和相关测试通过；既有亮/暗主题、窗口控制、聊天、搜索、模型和过渡无变化。代码量减少不是唯一验收条件，入口和依赖更清晰才算收益。

**R3：服务器入口拆分，列为可选后续批次。**

preachermanServer.mjs 有 2,545 行。可在现有测试可用时，优先提取边界清楚的配置读取/输入处理函数，或选择一小组独立只读路由；保留统一错误处理、来源校验、请求解析、路径匹配顺序和资源清理。

第一轮不同时迁移任务执行、审批、队列、状态存储，不改接口语义，不引入新框架或“万能路由抽象”。暂不把 R3 和磁盘清理捆在一起：它不能明显释放空间，验证成本也更高。如果选做 R3，会重建 sidecar 并增加针对该组接口的行为回归。

**10．避免清完又长回去**

拟采用的留存规则如下，具体作为本次方案的一部分供审阅，不在本轮自动启用：

| 类别 | 建议规则 |
|---|---|
| 正式桌面备份 | 继续使用已有最新三个完整验证备份规则，并保留清单固定的回滚对；用现有 Prune-DesktopBackups.ps1，不另造无限备份 |
| 失败发布 | 保留最新未解决故障的一套诊断材料；解决后保留报告，按清单淘汰大二进制 |
| 浏览器验证产物 | 当前发布证据、最近两轮通过结果、最新未解决失败；其余超过 30 天列入清理候选 |

清理工具应默认只读预览，输出编号、解析后的绝对路径、文件数、字节数、保留理由和处理结果；批准范围内再执行精确白名单。执行前复核路径仍在预期目录，拒绝意外的联接/符号链接，检查进程占用。Windows 文件操作统一在 PowerShell 中完成，不跨 shell 拼接删除命令。
