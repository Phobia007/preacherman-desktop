# Character voice conversation

Activate a character in Asset. In that character's Settings → Execution Mode, connect a signed-in Codex CLI or save a tested API connection. The bottom-right waveform starts voice conversation; click it again to stop. The three-dot audio menu retains microphone and speaker selection. No transcript, reply, input field or subtitles are rendered.

The first implementation uses installed Windows desktop speech recognition and synthesis, plus the selected real model. This machine has Chinese (Simplified) recognition and Chinese/English synthesis. Recognition language is independent of the English interface. Windows dictation accuracy and its generic installed voice are the current quality limits; this is not a cloned character voice. It needs no additional speech API key. Model calls still use the selected CLI login or API account.

Each catalog character has a stable identity, an independent execution selection, rule/skill slots and a memory namespace in `characters.v1.json` under the existing local service data directory. On first access, a character snapshots the global execution default. Later global changes do not replace that selection. API credentials remain in the shared connection store; they are not duplicated in character records. Character identity is supplied as server-owned model instructions. Tool execution remains disabled.

The existing microphone meter feeds a packaged AudioWorklet. It preserves a short lead-in and ends a phrase after one second of silence, with a twenty-second phrase bound and a forty-five-second idle shutdown. The microphone is released while recognizing, waiting for the model and playing a response, then reopened automatically. Stopping, changing character, changing execution settings or unmounting cancels the active request and playback. Audio and transcripts are not written to disk. Recent context is kept only in bounded process memory, isolated by character and voice session, and expires after thirty minutes. Info Map is unchanged.

Windows speech runs a fixed, hidden PowerShell program with JSON stdin and memory streams. User speech never becomes executable code. Requests are bounded, validated and cancelled when the client disconnects; owned children terminate at completion. A deployment must include both the rebuilt sidecar and the packaged host.

Verification: `tests/character-voice.test.mjs`, existing Codex/execution/audio/provider tests, type checking and a real native voice flow in both appearances. Synthetic speech verifies repeatable recognition → real character response → decoded non-silent playback. The native microphone is separately opened and stopped to verify hardware permission and capture. Personal microphone/accent quality still requires the user's own spoken trial.
